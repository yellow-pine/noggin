# README system diagram: research (2026-11-01)

## 1. Best practices

- **Level.** The README diagram is a C4 container view: a container is "a runtime boundary around some code that is being executed" ([C4 container](https://c4model.com/abstractions/container)).
- **Notation** ([C4 notation](https://c4model.com/diagrams/notation)): a title; a key for notation and acronyms; each element gets a type, a short responsibility and its technology; every line is one-directional, labelled specifically ("not Uses"), and container lines name the protocol; colour consistent, safe for greyscale and colour blindness; the diagram "can stand alone".
- **Colour and alt text.** Colour must not be the only cue ([WCAG 1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color)). A complex image needs a short alt text plus a longer description ([WAI complex images](https://www.w3.org/WAI/tutorials/images/complex/)). Mermaid's `accTitle`/`accDescr` become `<title>`/`<desc>` with `aria-labelledby`/`aria-describedby` ([Mermaid accessibility](https://mermaid.js.org/config/accessibility.html)).
- **Direction and grouping.** Mermaid supports `subgraph … end` and `LR`/`TB` layouts, but a subgraph's own `direction` is ignored once its nodes link outside it ([flowchart syntax](https://mermaid.js.org/syntax/flowchart.html)). Inferred: LR follows the reading order; grouping by deployment boundary (Mac vs Mech) makes the Wi-Fi edge cross it.
- **Size.** C4 gives no box count. Inferred: 5 to 8 boxes, 2 or 3 short lines each.

**Version drift (verified today).** GitHub's Mermaid viewer bundle calls `renderer.draw(…, "12.2.0", …)`, and its defaults are `layout:"elk"`. Material 9.7.7, the version pinned in uv.lock, loads `unpkg.com/mermaid@11/dist/mermaid.min.js`, so it gets 11.17.x with dagre. Mermaid 12.0.0 is breaking: "Existing flowcharts … will re-lay out and recolour; add `layout: dagre`, `theme: default` and `look: classic` to keep the old look" ([12.0.0 notes](https://github.com/mermaid-js/mermaid/releases/tag/mermaid%4012.0.0)). So the README diagram lays out differently on GitHub and on the site unless the block pins `layout`.

**Dark mode for images.** GitHub supports `<picture>` with `prefers-color-scheme` sources ([GitHub quickstart](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github)). Inferred: an SVG's own media query follows the OS setting, not GitHub's theme setting.

## 3. Examples

- **PX4.** The [architecture page](https://docs.px4.io/main/en/concept/architecture) shows a large SVG in two bands: middleware above, flight stack below. Its source is a draw.io file on Google Drive, and a comment warns arrows can come out wrong on export ([source](https://github.com/PX4/PX4-Autopilot/blob/main/docs/en/concept/architecture.md)). The drift ADR 0009 forbids.
- **Reachy Mini desktop app** (Pollen Robotics). The [README](https://github.com/pollen-robotics/reachy-mini-desktop-app) uses a Mermaid `flowchart TB` with subgraphs per runtime (Frontend, Backend, Python Sidecar, External, Hardware). Its edges carry the protocol: `IPC`, `WebSocket 20Hz`, `WebRTC :8443`, `Serial/USB`. Good edge labels; about 17 boxes, too many for a front page.
- **Home Assistant.** The [architecture overview](https://github.com/home-assistant/developers.home-assistant/blob/master/docs/architecture_index.md) shows a 3-layer stack (OS, Supervisor, Core): one bullet per layer, then one committed SVG with alt text.

## 4. Recommendation

1. **Keep a Mermaid flowchart in the README (recommended).** The README is its source, GitHub and the site render it, and it needs no CI or committed output. Add `layout: dagre` (or `elk`) in the frontmatter so the layout is the same on GitHub and the site, plus `accTitle`/`accDescr`, `LR`, the two groups, protocol edge labels and a one-line key under it. Not a picture of the Mech, so Blender's rule does not bind it (inferred).
2. **D2 source, with the SVG built in CI and served from the site.** It looks better (sketch mode, a dark theme) but adds a binary to CI. The README needs an absolute site URL (the last deploy, not the PR's version); dark mode follows the OS.
3. **Excalidraw or draw.io.** Hand-made look; manual edits, no text diff.
4. **Not recommended:** `architecture-beta` (beta, no edge labels, icons need registration), Mermaid C4 (fixed style, no legend) and Graphviz/PlantUML (no gain over D2).

**Conflicts in the current diagram** (sources: [ADR 0003](https://github.com/yellow-pine/noggin/blob/main/docs/adr/0003-noggin-service-owns-the-link.md), [ADR 0005](https://github.com/yellow-pine/noggin/blob/main/docs/adr/0005-wifi-first-usb-fallback.md), [GLOSSARY](https://github.com/yellow-pine/noggin/blob/main/GLOSSARY.md)):

- The hooks-to-service edge is unlabelled; ADR 0003 says it is a Unix socket.
- The diagram puts the USB-C fallback on both Core edges, but ADR 0005's known limits say "the USB fallback assumes the eyes Core" (`USB_CORE`).
- The diagram says "jaw" and "Turn"; GLOSSARY says "mouth" and "turn".

## 6. Serving it from the site (#265)

Material 9.7.7's bundle loads Mermaid only when `typeof mermaid == "undefined"` (or a stray `#mermaid` element), from
`https://unpkg.com/mermaid@11/dist/mermaid.min.js` (read in `material/templates/assets/javascripts/bundle.*.min.js`); its
diagrams docs show the override, a global `window.mermaid` defined before the bundle
([Material diagrams](https://squidfunk.github.io/mkdocs-material/reference/diagrams/)). So a site-served script that
fails to load (or fails its integrity) still falls back to that floating CDN copy. A `Content-Security-Policy` of
`script-src 'self' 'unsafe-inline'` closes that door: every other script the site ships is its own or inline (Material's
`__md_*`), checked on the built pages. Material's privacy plugin would also self-host external assets, but it fetches
whatever unpkg's `@11` is at build time, with no hash check, so it does not pin.

MkDocs runs hook files named in `mkdocs.yml` `hooks:` as plugins, any plugin event without `self`
([hooks](https://www.mkdocs.org/user-guide/configuration/#hooks)): `on_post_build` copies the checked file into the site,
so `make site`, the pages workflow and test_site.py's build all get it.

mermaid-cli 11.17.1 launches Puppeteer with `headless: "shell"` (its `src/index.js`), so only
`chrome-headless-shell` is needed; Puppeteer 25 skips the full Chrome download when `PUPPETEER_CHROME_SKIP_DOWNLOAD` is
set (its `getConfiguration`). `npx` installs into `~/.npm/_npx/<hash of the package specs>`, Puppeteer's browsers into
`~/.cache/puppeteer`: those two are what CI caches.
