Local: nothing in docs/references or docs/research greps for espnow/WLAN/aioble/webrepl (only build-notes.md L49 firmware string, L99 "Core 1 relays to Core 2 by ESP-NOW" = designer's setup). Stock manifest lists only .py/.mpy files, no radio code. Frozen (not on FS): bbl_product, ulogger, rc_module, ble_module, shutter_module (research/2026-10-31-hooks-serial-launchd.md L75).

Stock RC pairing (rc_module is frozen, source not public): docs/cyberbrick_core/lib/rc_module.rst documents rc_master_init/rc_master_data/rc_slave_init/rc_slave_data; data = tuple [L1,L2,L3,R1,R2,R3 ADC 0-4095, K1..K4 0/1]; "paired" state 0/1/2 "determined during pairing". Channel, MAC handling, wire format: NOT visible (inside frozen module). Whether stock RC uses ESP-NOW vs another 2.4 GHz proto is not stated upstream; build-notes' "ESP-NOW" is the designer's claim.

Community (not stock): rotorman/CyberBrick_ESPNOW receiverPY/truck/truck.py: Wi-Fi channel fixed 1 (valid 1-11, edit constant); bind = receiver broadcasts own MAC to ff:ff:ff:ff:ff:ff every 500 ms while button held; payload CRSF 16 ch 11-bit (173/992/1811). Their README calls stock "original codebase", i.e. alternative to it.
